# Architecture

## Dependency direction

```text
SwiftUI views
    └──► RobotViewModel ───► GameControllerInput
              │
              ├──► RobotSession actor ───► RobotTransport
              │         (ROBControlCore)       ├── SimulatedRobotEndpoint
              │                                └── CerebroRobotTransport
              │                                      (ROBCerebroTransport)
              │                                         ├── ROBControlClient
              │                                         └── ROBVideoClient
              │
              └──► VideoPipelineCoordinator
                        └──► H264VideoReceiver (ROBVideoPipeline)
```

`ROBControlCore` imports only Foundation. It owns the domain model, safety state machine, simulator, connection protocol, and video-domain messages without depending on Network.framework or a particular robot wire format.

`ROBCerebroTransport` imports Network.framework, Security.framework, and CryptoKit. It owns Keychain pairing, Bonjour discovery, pinned TLS 1.3 QUIC parameters, reciprocal HMAC authentication, control compatibility encoding, `RVID` framing, and `RBVD` media decoding. Cerebro-specific and historical ROBController wire shapes terminate at this target.

`ROBVideoPipeline` imports Core Video, VideoToolbox, Core Media, and AVFoundation. The app target owns observable lifecycle state and the SwiftUI display wrapper, not codec parsing or transport framing.

## Pairing and identity

The pairing code is an out-of-band enrollment artifact issued by Cerebro, not a server identity generated by the controller. `ROBCerebroPairingStore` accepts an `operatorController` `ROBCTL2:...` code and stores exactly one local Cerebro profile in a device-only Keychain item. Installing another valid code intentionally updates that profile; removing it deletes only the local item and does not revoke the server-side device record.

The stored profile contains:

- Cerebro's robot UUID;
- this Vision Pro's unique controller UUID;
- the `_robctl._udp` service and `robctl/2` ALPN contract;
- Cerebro's exact SHA-256 leaf-certificate pin;
- the controller's 256-bit pairing secret; and
- its server-issued role and display metadata.

Each physical controller must use a different code. A copied credential is the same cryptographic device, so Cerebro's duplicate-session and revocation rules cannot distinguish the copies.

Cerebro's canonical-certificate migration is a one-time re-enrollment boundary. If the migration replaced the old leaf certificate, the old Vision profile has a deliberately stale pin and must be replaced with a fresh Cerebro-issued credential after the stale server record is revoked. Ordinary Cerebro restarts must reuse the canonical certificate.

## Production connection flow

```text
install Cerebro-issued operator credential
    ▼
browse _robctl._udp and match robot_id + ver=2 + alpn=robctl/2
    ▼
pin Cerebro's leaf, establish QUIC/TLS 1.3, complete reciprocal control proof
    ▼
retain Cerebro's exact 16-byte control-session UUID
    ▼
attempt _robvideo._udp discovery and match robot_id + ver=1 + alpn=robvideo/1
    + codec=h264 + delivery=reliableStream, then establish QUIC/TLS
    ▼
success: complete the video proof and receive camera capabilities
failure: tear down video state and use an empty camera list
    ▼
publish a ready RobotSession handshake containing the control UUID
and either the authenticated camera list or no cameras
```

The controller never treats Bonjour TXT data as authentication. Discovery uses the credential's robot UUID only for routing; the certificate pin and reciprocal secret proof establish the peer identity.

The app declares `_robctl._udp` and `_robvideo._udp` in `NSBonjourServices` and supplies `NSLocalNetworkUsageDescription`. A user denial of Local Network permission prevents discovery and is surfaced as a connection failure rather than falling back to an arbitrary host.

## Concurrency boundaries

- `RobotViewModel` and `GameControllerInput` are main-actor isolated.
- `RobotSession` is an actor and is the sole owner of connection transitions, command sequence allocation, video-subscription state, and dead-man state.
- The Cerebro transport, `ROBControlClient`, and `ROBVideoClient` own their Network.framework connections behind actor isolation; network callbacks cross into actors before changing state.
- Connect and disconnect operations carry identities and are revalidated after every suspension. Concurrent disconnect callers share one teardown, reconnect cannot race that teardown, and a late acceptance for a cancelled video request is immediately unsubscribed.
- Every transport is `Sendable`; the simulator is an actor.
- Views consume a bounded, newest-value `AsyncStream<RobotSessionSnapshot>` rather than observing transport callbacks directly.
- Every open media channel has a unique ownership token. Session and transport state are revalidated after asynchronous opens, preventing stale reconnect work from escaping or closing a replacement channel.
- The receiver enqueues media directly into `AVSampleBufferVideoRenderer`; only throttled statistics reach Observation and SwiftUI. SPS-derived coded and presentation dimensions must match the negotiated stream before decoder use.

## Safety contract

Every drive envelope contains a monotonically increasing domain sequence and a short input lease. The controller sends decisions at 10 Hz by default. The Cerebro adapter translates the normalized domain command into the established ROBController application payload only after the secure control connection is authenticated.

Emergency stop is latched. Reconnection, controller discovery, or scene reactivation cannot clear it. Resetting emergency stop leaves motion disarmed and requires a separate arm action.

The application scene invalidates motion on inactive/background transitions. Physical game-controller samples are event-driven: stale framework state is not promoted into fresh operator intent. Cerebro remains responsible for the definitive receive-side watchdog and neutral/braked state when a real controller session disappears.

## Connection state

The session publishes explicit phases:

```text
disconnected → connecting → handshaking → connected
      ▲                                      │
      └──────────── disconnecting ◄──────────┘

Any active phase may enter failed.
```

For Cerebro, readiness means control discovery, pinned TLS, reciprocal control proof, and acquisition of the live session UUID completed. The adapter makes a bounded attempt to authenticate video and enrich the handshake with cameras, but a video discovery or authentication failure yields an empty camera list instead of failing control. Readiness does not mean that motion is armed or a video subscription is active.

## Video boundaries

The simulator and Cerebro expose the same `RobotVideoDataTransport` domain boundary but route it differently.

Simulator path:

```text
accepted simulator subscription
    → SyntheticPixelBufferSource
    → VideoToolbox real-time H.264 encoder
    → BoundedInMemoryVideoChannel
    → VideoStreamValidator + H264SampleBufferFactory
    → AVSampleBufferDisplayLayer.sampleBufferRenderer
```

Cerebro path:

```text
authenticated _robvideo._udp / robvideo/1 connection
    → capabilities + subscribe/response on that video connection
    → RVID ordered frame carrying RBVD codec configuration/access unit
    → strict session, stream, sequence, size, AVCC, and SPS/PPS validation
    → VideoStreamValidator + H264SampleBufferFactory
    → AVSampleBufferDisplayLayer.sampleBufferRenderer
```

The production subscription is H.264 `reliableStream`; QUIC datagrams are not advertised by Cerebro. Network.framework may segment the ordered QUIC stream internally, but the application receives one bounded, complete codec-configuration or AVCC access-unit message from the `RVID` framer. There is no JSON/base64 media path and no application-level datagram-fragment reassembly in this profile.

## Amber arm feedback boundary

Amber gateway telemetry remains owned by Cerebro. Cerebro projects its validated
seven-joint samples onto the existing authenticated ROBControl application channel;
the Vision client decodes them into `RobotArmMeasuredState` and publishes them in the
newest-value session snapshot. The app's telemetry panel is currently diagnostic;
a future RealityKit arm renderer should consume the same measured snapshot and mark
stale feedback rather than holding an old pose as live.

The reverse path transports `RobotArmTargetIntent` only. The message is bounded,
leased, sequenced, and bound to both the paired controller identity and live session.
Cerebro's bridge applies its independent, local, time-limited controller authority
and returns a preview/rejection disposition. No transport or view calls the Amber
gateway, and the v1 disposition schema makes execution eligibility permanently
false. Cerebro also checks the exact calibrated per-joint B1 limits, current live
session, telemetry age, seven position modes, 0.10-radian update delta,
0.20-radian/second requested average speed, and one in-flight target per arm before
marking a target as having passed internal preflight. Calibrated IK, continuous
dead-man behavior, measured completion/hold-on-expiry, and the final hardware
executor remain a later Cerebro-side layer.

Video capabilities, subscription requests and responses, receiver feedback, unsubscribe, stream-ended events, and media all use `_robvideo._udp`. None of them is placed on the `_robctl._udp` connection. `RobotSession` models these as control-domain operations, while `CerebroRobotTransport` routes them to the independent physical video channel.

Every video request carries the exact live control-session UUID. Cerebro authorizes the request only when that UUID is still registered to the same authenticated `operatorController`. A locally generated or stale UUID fails closed. Control disconnect, session replacement, credential revocation, video failure, scene suspension, or explicit unsubscribe closes the media channel without weakening control safety. Video loss ends active streams but deliberately leaves the authenticated control connection ready. The adapter does not hot-reconnect video or republish capabilities during that session; reconnecting the Cerebro endpoint performs a fresh video attempt.

The pipeline forces a keyframe on start and recovery and stops on consumer cancellation, scene inactivity, unsubscribe, or disconnect. A sequence gap invalidates predictive frames until another IDR arrives. Duplicate or stale traffic is discarded where safe; malformed current-session media fails the stream closed.

## Current production profile

- One monoscopic `front` camera.
- H.264 AVCC only, up to 960 x 540, 20 fps, and 1.5 Mbit/s.
- Ordered `reliableStream` QUIC delivery; no QUIC datagrams.
- Live viewing only; no recording, replay, audio, depth, stereo, or spatial-video track.
- Cerebro permits at most two authenticated video controllers and one active stream per video connection.
- The control application payload remains a private compatibility translation until all robot applications share a typed replacement. The `ROBControlCore` domain contract is not changed to match that legacy representation.
